## Rules for every workstream

1. Read `AGENTS.md`, `.opencode/HARNESS.md`, `.opencode/ROUTES.md`. Do not commit; the orchestrator commits.
2. Own only your listed files. New code goes in NEW files/modules. Shared hot files
   (`crates/flamewm-wm-wayland/src/{state,handlers,main,input}.rs`, `ui/shell/panel*.html`) get
   only minimal registration edits: re-read the file immediately before editing, use small
   exact-string Edit calls, never rewrite or reformat whole shared files, no `cargo fmt` on
   files you do not own (format only your own files with `rustfmt <file>`).
3. Build isolation: `CARGO_TARGET_DIR=/run/media/linsaftw/SDD/target-swarm-<N>`, `CARGO_BUILD_JOBS=3`.
4. clippy is not installed. Require zero rustc warnings, `cargo test -p <touched>` exit 0, and
   record real unpiped exit codes. Add unit tests for every new pure-logic unit.
5. Performance contract: no timers under 50 ms when idle, no per-frame allocation in hot paths,
   no new always-on threads (use event-loop sources or short-lived/pooled threads), bounded
   caches, no unbounded Vec growth. Memory: share, do not duplicate; lazy-init optional features.
6. No `.vendor/**` as dependency. Exceptions need explicit `docs/ARCHITECTURE_EXCEPTIONS.toml` entries.
7. Report: files changed, commands+exits, what was not verified (runtime/visual), one-line risk.
8. Honest scope: if a sub-item is not feasible, skip it and say so; do not stub.

## Workstreams

1. **WL client compat** (new `crates/flamewm-wm-wayland/src/protocols/compat.rs`): primary-selection,
   cursor-shape, pointer-constraints + relative-pointer, keyboard-shortcuts-inhibit,
   xdg-activation (focus-steal policy: activate only when token valid), idle-inhibit
   (fed to the idle/lock timer), text-input-v3 + input-method-v2. Goal: Qt (qmmp), browsers, games, IMEs.
2. **WL outputs** (new `.../output_layout.rs`; edits to `drm/mod.rs`, model output fields): true multi-output
   layout (per-output rect, windows belong to an output, pointer crossing, per-output work area),
   fractional-scale-v1 + viewporter use, wp_presentation, xdg-output, consume
   `per_output_scale`, mode/refresh selection policy (highest refresh at preferred resolution,
   user override), hotplug robustness; logical vs physical size plumbing.
3. **WL capture + toplevel + gamma** (new `.../protocols/capture.rs`): ext-foreign-toplevel-list +
   wlr-foreign-toplevel-management (external taskbars/switchers), screencopy/ext-image-copy-capture
   (feeds `flamewm-screenshot`), wlr-gamma-control (night light backend, uses `flamewm-api/blue_light.rs`).
4. **System tray** (new crate `crates/flamewm-tray`; panel edits only inside element `#tray`):
   StatusNotifierWatcher/Host over `flamewm-dbus-reactor`, SNI items (icon, tooltip, activate,
   context menu via com.canonical.dbusmenu), icon cache shared with the shell icon loader, legacy
   XEmbed not required. Overflow chevron when > N items.
5. **Overview + hot corners** (new `ui/shell/overview.html`, shell module `overview.rs`, control action):
   workspace grid with live window thumbnails (reuse existing buffers; no extra copies), type-to-search
   launcher/finder, drag windows between workspaces; hot-corner dispatch consuming `hotCorner.*`
   (pointer dwell with a 150 ms debounce; no polling timer), actions none/overview/show-desktop/lock.
6. **Window management** (edits `flamewm-window-core`, new `.../snap_preview.rs` in wm-wayland and
   rounded preview in wm-x11 `snap_preview.rs` via X Shape or ARGB): consume `edgeSnap.enabled` and
   `thresholdPx`; translucent rounded (radius from token) snap preview on both backends; keyboard
   tiling (Super+arrows, quarter tiles, restore), per-app window rules (size, workspace, float) from
   a small TOML in the config dir with hot reload; remember window geometry per app-id.
7. **Displays + Night Light + Accessibility settings** (flamewm-settings, ui/settings.html/.css, platform
   display service): Displays page (resolution, refresh, scale, arrangement, primary, orientation) over
   the existing display transaction service with auto-revert; night light schedule (sunset/sunrise or
   manual, temperature); accessibility group in platform settings (high contrast, reduced motion, text
   scale, cursor size, sticky keys, slow keys) with `:root` variables applied via existing `var()` support.
8. **Notification center + quick settings** (integrations-linux notifications.rs, new
   `ui/shell/notification-center.html` and `quick-settings.html`, shell module; panel edits only inside
   `#status-cluster`): history with grouping, actions, DND, per-app mute; quick settings flyout
   (volume, brightness, network, bluetooth, night light, DND, power profile) reusing existing services.
9. **Responsiveness + memory** (flamewm-shell, flamewm-ui-document, flamewm-profiler, flamewm-desktop,
   flamewm-reactor; NOT render-compiler): read `docs/PERFORMANCE*.md` first, measure with the profiler,
   then fix the top measured hotspots: parallel startup of independent shell panels, pooled
   decode threads for icons/thumbnails/wallpapers, coalesced redraw, shared glyph/icon atlas dedupe,
   cheaper idle (event-driven only). Every change needs before/after numbers or a clear
   complexity argument; no speculative threading.
10. **CSS engine + design system** (crates `flamewm-render-compiler`, `flamewm-ui-document`, `ui/**`
    except settings.html/.css and notification/quick-settings/overview html): add `calc()`, `@import`
    partials/templates (compile-time, cycle-checked), nesting, `:is()/:where()`, more shorthands,
    on-disk compiled-CSS cache keyed by content hash; link the shared token sheet from shell pages and
    replace hardcoded literals in `ui/flamewm.css`, `ui/shell/flamewm.css` with tokens, byte-identical
    output for unchanged pages (prove with a compile-diff test).
