# UI/UX Consistency Audit

Scope: `ui/**` HTML/CSS as compiled by `flamewm-render-compiler` (via `include_str!`), settings toggle wiring, and dead CSS. Base: `6aa187a9`.

## Method and limits

- Static: pseudo-state support in `crates/flamewm-render-compiler/src/css.rs`, `:focus`/`:disabled` grep over `ui/`, class-reference scan of every CSS class against `ui/**/*.html`, `ui/**/*.js` and `crates/**/*.rs`, settings key to Rust consumer trace.
- Runtime: not run in this pass. No hover, focus or theme screenshots were taken. Visual claims below are unverified.
- Not covered: colour-token tidy-up across all apps, radius/spacing normalisation, tooltip coverage, scroll behaviour, truncation, and `.vendor/cosmic-*` comparison. These are open.

## Findings

### F1. No keyboard focus state exists anywhere (open, needs compiler + runtime work)

- `:focus`, `:focus-visible` and `:disabled` appear in zero UI stylesheets.
- The render compiler accepts only `:hover`, `:active`, `:root` (`css.rs:323-326`). Any `:focus` rule would fail compilation with `unsupported pseudo-class`.
- Only 3 `<input>/<select>/<textarea>` elements exist in `ui/**/*.html` and one `tabindex` in `ui/settings.html`.
- Disabled looks come from `.disabled` / `.is-disabled` classes only (`.media-control.is-disabled` opacity 0.4 is the one clear case).
- Fix needs a `:focus` pseudo-state in `flamewm-render-compiler` and a focus signal from the shell/UI owner. Not changed in this pass.

### F2. Dead CSS rules (fixed)

Each class was confirmed absent from all HTML, JS and Rust sources (`rg -w`) before removal:

| File | Removed | Note |
| --- | --- | --- |
| `ui/explorer/explorer.css` | `.place-dot` | no reference |
| `ui/task-manager/task-manager.css` | `.dangerous` | no reference |
| `ui/settings.css` | `.display-card .setting-block` | `display-card` no reference |
| `ui/shell/flamewm.css` | `.selected-monitor` | no reference (the root prototype copy is left, see F5) |
| `ui/shell/flamewm.css` | `.network-actions`, `.popup-tabs` from the `.audio-row` selector list | `popup-tabs` appears only as a canary scenario name, not as a class |

Kept on purpose: `.is-selected`, `.is-current` (generated in `crates/flamewm-settings/src/view.rs`), `widget-analog-n*`/`widget-edge-*` (generated by name in `ui/desktop` and render code), `pal-*` (generated palette classes).

### F3. Settings toggle without behaviour (open, decision needed)

- `settings.toggle.lockOnSuspend` ("Lock on suspend") is parsed and stored (`crates/flamewm-platform/src/settings.rs:339,465,1247`) but no runtime code reads `lock_on_suspend`.
- Wiring needs a logind `PrepareForSleep` subscription in the reactor/session owner, which is outside this UI pass.
- Alternative is removing the row and key. Not done: removing a persisted key needs a legacy-parse decision.
- Other settings toggles checked by non-test readers: `lockShowDate`/`lockShowUsername` (`crates/flamewm-lock/src/settings.rs`), `assistant.speechToText`/`textToSpeech` (`crates/flamewm-assistant/src/lib.rs`), `showContentWhileDragging` (`flamewm-wm-x11`), `pointerRawInput` (`flamewm-wm-wayland/src/drm/input.rs`) all have live consumers.
- Not checked: whether each consumer re-applies the value live without restart. Needs runtime verification.

### F4. Theme and contrast

- `ui/flamewm.css` and `ui/shell/flamewm.css` define only a dark token set on `:root`. No `prefers-color-scheme` or light token set exists, so light-theme contrast is not applicable today.
- A global text-shadow gate exists (`ui_text_shadow` in `flamewm-render-core/src/paint.rs`), so the opt-out is code-level, not per-element.
- Hard-coded surface fills are common and bypass tokens: `#292c2f` (`.nav-row:hover`), `#3b3f43` (`.title-button:hover`), `#303438`/`#383c40` (settings buttons), `#25282b`/`#272a2d`. Tokenising these is open.

### F5. Duplicate and orphan stylesheets

- `ui/flamewm.css` (root) is not included by any runtime `include_str!`. It backs the prototype `ui/index.html`, which `FINISH_LINE_VERIFICATION.md`, `tools/ui_contract_guard.py` and `tools/accent_default_guard.py` reference. It is a parallel copy of `ui/shell/flamewm.css` and has drifted. Not removed, because tooling depends on it.
- `ui/desktop/index.html` and `ui/shell/*` are runtime sources.

### F6. Pre-existing guard failures (not introduced here)

- `tools/ui_contract_guard.py`: 1 error (`surface_border_opacity default != RIM_PERCENT`, a platform default mismatch), 22 warnings.
- `tools/accent_default_guard.py`: FAILED with 14 hardcoded default accents, including `ui/shell/flamewm.css:1` and `ui/imageviewer/imageviewer.css:1`.
- Ran after the F2 edits. The failing lines are outside the deleted rules. Not re-run at `HEAD`.
