PARTIAL: every standard size knob (strip, debug, LTO, codegen-units, panic) was already at its smallest safe value, so the only remaining size headroom was code generation for idle-resident binaries. Production edits landed: `flamewm-terminal` added to the `opt-level = "s"` group (Cargo.toml:116-117, concurrent worker), and eight purely UI/event-plumbing app bins — `-archiver-app`, `-assistant`, `-explorer`, `-finder`, `-imageviewer`, `-settings`, `-task-manager`, `-audio-helper` — moved from `s` to `z` (Cargo.toml:94,97,100,103,106,112,123,126). Latency-sensitive `-wm`, `-desktop`, `-shell`, `-lock`, `-apps` and `-terminal` were deliberately left at `s`. All edits are UNBUILT: no cargo, build, binary-size/RSS measurement or commit was run here; rendered output stays pixel-identical because these are code-generation-only changes, with the residual risk of slightly slower startup/event handling in the affected apps. `panic = "abort"` and its conflict with `diagnostics::guard` remain untouched and are owned by p88; removing it would grow the binary, and adding it is not needed.
