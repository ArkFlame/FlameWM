# u123-mod-integrity

Read-only integrity audit of module declarations and embedded-file references under `crates/**/src`.
No source edits were needed: every declaration resolves to a file on disk.

- Scope: 95 crates, 1,291 `.rs` files under `crates/**/src`, 1,222 `mod`/`pub mod`/`pub(crate) mod` declarations.
- Resolution rules honoured: ordinary `NAME.rs` then `NAME/mod.rs`; for `lib.rs`/`main.rs`/`mod.rs` the base is the file's directory, for any other file it is `<file dir>/<file stem>/`; `#[path = "..."]` attributes override (1-3 attribute lines above the declaration are inspected, including inline module blocks); `mod NAME { ... }` inline blocks ignored because they declare no file.
- Result: 0 missing declarations. No `mod` name points at a non-existent `.rs` or `mod.rs`.
- `include_str!` / `include_bytes!`: 301 call sites. 229 are literal paths (192 unique targets) resolved relative to the declaring file; 0 missing. 70 are `concat!(env!("OUT_DIR"), ...)` renderer artifacts generated by build scripts, 1 is multiline (`assets/branding/flamewm-wallpaper.webp`, present), 1 is a comment in `crates/flamewm-desktop/build.rs`. No embedded-file path is dangling.
- Git tracking (`git ls-files`) was NOT executed: the shared-checkout brief forbids `git` for workers, and the checkout's `.git/index` is sparse (few `crates/**/src` entries), so tracking cannot be inferred from disk. Every audited path exists and none is matched by a repository ignore rule (`rg --files` lists all 1,291 source files and all 192 include targets). Orchestrator should confirm tracking with `git ls-files --error-unmatch` on the batch before commit; zero deletions/renames were found by this audit that could produce untracked files.

Composition impact: none directly (audit unit); it removes the risk of a cfg-gated or deleted-module gap becoming a build break in a later perf unit.
