# u114 lockscreen changes
- run: the lock tick timer dropped from 20 Hz to 1 Hz (`TICK`). Keys, pointer motion, control snapshots and worker results each wake the reactor themselves, so the timer now only covers what the server does not announce: grab retries, screensaver phases, DPMS settling and the minute clock.
- run: idle per-turn X work fell with it — `XQueryPointer`, `XPending`, `XGrabKeyboard`/`XFlush` and the per-surface `XRaiseWindow`/`XFlush` no longer run 20 times a second while the screen sits locked and untouched.
- run/tick: the grab retry and the stacking raise are safety nets, gated to `HOUSEKEEPING` (1 s) so the 30 Hz Ribbons pacer wakes no longer re-grab and re-raise every surface per animation frame. Focus and keymap events still re-grab immediately through `read_keys`, and a shown or rebuilt surface raises itself.
- run/power/input: added `crate::wake::Waker`, a one-byte wake over the existing pacer socket pair. PAM, power actions and the capability fetch now nudge the loop after their send, so authentication and power results apply at once instead of at the next tick — the tick interval is free to grow without adding unlock latency. Authentication stays on its worker thread; the render thread still never blocks on PAM.
- Blur confirmed computed once: `document::background_image` blurs at image construction, `base_background` keeps the result, and repaint only re-applies view/power. No per-frame blur, decode or crop on the idle path.
- Composition shift (expected): lock idle wakeups 20/s -> 1/s, and each of those wakeups now costs 1 pointer round trip instead of the old 20/s; during the Ribbons screensaver, ~3 X requests per surface per frame become ~3 per second. Share of the compositor blend for "locked and idle" moves toward zero; the PAM/power result path becomes event-driven instead of timer-sampled.
- Checks: static reading only (worker units run no cargo/git); orchestrator builds and tests.
