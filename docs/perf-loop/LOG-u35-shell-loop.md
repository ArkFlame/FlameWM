# u35-shell-loop

- shell tick / OSD: `refresh_dynamic` now returns the reconciled `ChangedDomains` it already computed, and the tick threads that value to the OSD and dock owners instead of each re-deriving state. Expected composition shift: removes one hidden state dependency and makes the following gates possible at no extra cost.
- app/timers `tick_osd`: once the first baseline observation succeeds (`osd_primed`), a turn with no system snapshot change and no pending OSD deadline skips `default_sink_level`, the brightness lookup and `OsdController::update`. Volume and brightness come only from the system snapshot, and the single hide deadline owns expiry, so the skipped work can never change the card. Workspace OSD keeps running every turn because it owns its own baseline. Expected shift: removes two system reads plus motion-scale work from every pointer-motion wake, the bulk of the event stream.
- app/dock `sync_dock`: added an early-out for an idle turn. When the dock has been published, no windows/workspaces/panels domain changed, the settings revision and snapshot presence match the last build, auto-hide is off, the auto-hide model has no pending frame (a slide such as auto-hide being turned off keeps stepping), and no dock drag, menu or launch bounce is active, the layout, frame, running Vec, name Vec, covered scan and backdrop capture are all skipped. The tick and the pointer path pass the snapshot change set plus a `force` flag; the tween path (`dock_pointer`) forces. Menu close and drag release invalidate the stored key so the pinned-open hold is stepped out even when auto-hide is off. Expected shift: the per-tick dock rebuild leaves the pointer-motion path; the dock only re-syncs on real domain, settings or animation changes.
- app/usage `tick_usage`: the provider list and interval are rebuilt and `UsageHost::configure` is called only when the settings revision differs from the last configured one. `UsageHost::tick` still runs every turn because it owns the fetch schedule. Expected shift: removes one provider `Vec` allocation per wake.
- main notification toast tick: `NotificationProvider::expire` is called only when its `next_deadline` is due. Reading the provider shows `expire` only removes entries whose own `expires_at` is at or before now, so a not-yet-due call is a no-op; the deadline is still published to the reactor wake each turn. Expected shift: removes a notification-map scan plus allocation from every toast wake before the first expiry.

## Regressions reviewed

- event_router/route menu-row gating: pointer, wheel and hover events keep an empty `menu_rows`. Pointer activation acts on the event action id and never indexes the row list; `overflow_activation_index` only fires for typed Enter/Space text and returns `None` for zero rows, and `overflow_menu_closes_on` runs only on key presses. Keyboard navigation still builds the rows, so no overflow behavior changed.
- app/settings full-reprojection split: a domain change sets `settings_projection_pending` in `refresh_dynamic`, and `project_panels_partial` re-projects the task slots for windows, workspaces and progress before the style pass runs. A real settings snapshot sets both the pending flag and `settings_full_reprojection`, so the first settings arrival and every accent/theme change still reproject every slot; a domain-only refresh deliberately reuses the slots it just projected.
- app/dock compare-before-clone: the previous-state compare covers frame, placement, names, entries and squared corners. Trash changes reset `dock_last` to `None` (`refresh_dock_trash`), which forces a rebuild regardless of the new early-out. A settings change bumps the revision, so the early-out cannot skip an accent or pinned-list rebuild. No skipped publish path was found.

## Skipped

- O5 per-tick allocation sweep: the remaining candidates (the fixed-size `earliest_wake` array and the per-domain settings style pass) are cheap stack work or only run on real changes, so no additional safe removal was made in this pass.
- No dead code was found in the owned paths that was provably unused across the crate; nothing was deleted to avoid touching shared helpers.
